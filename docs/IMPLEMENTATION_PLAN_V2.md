## 2. 设计收口判定：还有必要继续 Grill 吗？

### 2.1 当前无需阻塞开发设计的事项

- 默认 LLM model ID：通过 Provider 设置由用户选，未配置时引导；不写死未确认型号。
- 第三方图片 API 差异：先做协议 PoC/Adapter，每个模型做明确 capability test，不能依赖“聊天兼容”猜测。
- 模板具体措辞：作为可编辑的系统资源和测试样例，设计迭代；不改变已确认的“可自定义”。
- 并发数、任务超时、文件复制安全参数：有界保守默认、技术可配置，靠压测与测试收敛。
- 保存重复、断电补偿、目录失效：按不覆盖原文件和保留历史原则确定安全默认。
- ComfyUI output 节点差异：映射适配 + 真实 Workflow 验证，非新增产品选择题。

### 2.2 有意义但可推迟的用户决策

1. **视频生成/视频反推是否作为二期另一批交付**。这是唯一明显影响项目范围/工期的未确认产品决策；不阻塞当前图片设计。
2. 若希望“历史保留”的物理存储路径支持跨磁盘迁移，需要另一个数据迁移的产品规则；当前技术方案是历史单独持久化、原址可读、不自动迁移。
3. 如果希望删除历史时同步删除已入库资产，将违反当前安全隔离设计；若未来有此诉求需重新确认。

**阶段结论**：不用再发散二十多个问题。开始按本设计 PoC + 纵向切片实施；只在发现上述实质冲突时 Grill 一问一答。

### M0：工程基线与协议验证

**V2-01 基线检查与 V1 回归快照**
- 输出：核对 migrations 0001–0009、asset.prompt_text/source_type、ImportWorker、现有目录/回收站逻辑；整理最小 V1 冒烟清单。
- 验收：V1 项目/目录/导入/外部关联/回收站/原生拖出不变；有可重复运行的隔离测试数据。
- 依赖：无。先做。

**V2-02 第三方接口与 ComfyUI 协议 PoC**
- 输出：对两个可配置 OpenAI Compatible 端点（可用 mock + 用户实际实例）分别验证 Chat 视觉、文本优化、图片生成、图片编辑的请求/响应；验证一个 API Workflow 的上传/运行/拉取；记录差异表。
- 验收：失败时清楚报告哪个能力不支持；不提交任意真实素材到未经允许的测试服务；模型 ID/参数均从配置取得。
- 依赖：V2-01。**风险关卡**：协议不明时不要先做万能 UI 再硬适配。

### M1：Provider、模板、反推最短路径

**V2-03 Provider 连接与秘密管理**
- 输出：多实例 CRUD、自定义兼容入口优先、凭据安全存储、状态/能力测试、后端 API 和最简前端设置。
- 验收：多个第三方连接能共存，修改/删除互不干扰；API Key 不会作为明文返回或留在日志；无兼容能力的模型不能误报成功。
- 依赖：V2-02。

**V2-04 模型配置/能力 Schema/默认策略**
- 输出：视觉、LLM、生成、编辑能力模型配置；全局 GPT 图像默认、场景覆盖、临时选择优先级；动态 schema 基础。
- 验收：切换场景默认不污染全局设置；无 GPT 图像配置时给出引导；不支持参考图或输出比例的配置被前后端拒绝。
- 依赖：V2-03。

**V2-05 Prompt 数据迁移与安全保存**
- 输出：资产来源、prompt_origin、关联任务字段和 CAS 版本控制；已有 prompt_text 保留；扩展 V1 预览来源徽标。
- 验收：V1 旧数据 migration 前后 Prompt 内容逐字一致；已有 Prompt 未确认不会被 AI 覆盖；并发编辑时 409 给出明确提示。
- 依赖：V2-01。

**V2-06 图片反推模板与单图反推**
- 输出：内置模板、用户自定义模板管理；视觉 Provider 单图反推；预览内草稿/修改/复制/保存/覆盖确认。
- 验收：反推不是“找回原 Prompt”，草稿不会自动保存；已有 Prompt 要确认；支持错误与重试提示。
- 依赖：V2-03/04/05。

### M2：端到端图片生成与永久历史

**V2-07 AI 任务记录/独立调度器**
- 输出：ai_tasks 与 item 记录、受控并发、状态机、取消请求/安全重试、重启恢复标记；任务中心最小 UI。
- 验收：两个连接并行执行不阻塞导入/画廊；应用退出后任务可追踪；未知上游状态不盲目重复扣费。
- 依赖：V2-03/04。

**V2-08 永久历史物理存储与参考图快照**
- 输出：受控 AI 历史目录、临时 staging、SHA/文件完整性校验、失败补偿、输入参考图快照、历史文件 API。
- 验收：应用重启后还能浏览结果；将本地原参考图移动不影响历史快照；ComfyUI 原始 output 不被删除；历史不自动 TTL 清理。
- 依赖：V2-07。

**V2-09 GPT / Compatible 文生图最短闭环**
- 输出：生成模式与模型参数表单、一个已验证图片生成 Adapter、结果预览与任务中心/永久历史连通。
- 验收：输入 Prompt → 调用一个已配置 GPT 图像模型 → 结果留在历史而非资产库；任务失败时不留下损坏图片。
- 依赖：V2-04/07/08。

**V2-10 AI 生成结果手动入库**
- 输出：结果多选、已有目录树预选/确认、复制校验入库、资产来源/唯一 Prompt/任务关联、已入库标识。
- 验收：同任务 4 张结果只选择 2 张入库；原结果 4 张均留历史；已入库文件与历史文件物理生命周期分离。
- 依赖：V2-05/08/09。

### M3：LLM 优化、多图编辑、再创作

**V2-11 创作场景预设与 LLM 提示词优化**
- 输出：内置/自定义创作预设；按模板 LLM 优化、结果可编辑、跳过优化直接生成；默认文本模型配置。
- 验收：优化不会自动提交生图；用户可用专业 Prompt 跳过优化；最终入库的 Prompt 与实际提交文本完全一致。
- 依赖：V2-04/09。

**V2-12 统一多来源参考图面板**
- 输出：资产库选择、历史选择、本地文件、拖放、剪贴板粘贴；多图排序、用途标注、能力数量/格式校验；任务输入快照。
- 验收：混用三种以上来源、调整顺序，执行记录中次序一致；切换模型到较小图片上限时有明确错误/提示，绝不偷偷丢图。
- 依赖：V2-08/09。

**V2-13 图片编辑与模型动态参数**
- 输出：明确生成/编辑模式切换；多参考图编辑 Adapter；参数依能力变化；新编辑结果永久存历史。
- 验收：带参考图仍能选择“图片生成”；图片编辑不覆盖原图；新结果来源标记“AI 编辑”。
- 依赖：V2-09/11/12。

**V2-14 重新生成/变体/继续编辑**
- 输出：历史结果操作、按动作恢复配置、Provider 切换兼容性校验、每次新任务。
- 验收：三种操作输入不同且符合已确认规则；重生成不承诺像素一致；旧任务与结果不变。
- 依赖：V2-11/13。

### M4：ComfyUI、批量反推与高质量历史检索

**V2-15 ComfyUI Workflow 管理与执行**
- 输出：多 ComfyUI 实例、API Workflow 导入、参数输入/输出映射、预设与版本快照、执行及结果拉取。
- 验收：通过真实工作流跑通单图/多输入场景；节点变化被检测，缺依赖显示可理解错误；结果写入 Ryan_DAM 历史副本。
- 依赖：V2-03/07/08/12。

**V2-16 批量反推 + 审核保存**
- 输出：画廊多选、批量独立调用、逐项待审核列表、筛选无 Prompt、选择性保存与覆盖确认、单项失败/冲突处理。
- 验收：30 张中 20 无 Prompt/10 已有，保存前 10 份原 Prompt 不变；覆盖冲突不能静默成功；部分失败不影响其他结果。
- 依赖：V2-05/06/07。

**V2-17 生成历史画廊、任务分组与多维检索**
- 输出：永久历史双视图、按 Prompt/时间/模型/任务类型/入库状态/场景预设筛选、下载/手动删除与任务关联显示。
- 验收：跨应用重启完整检索；已入库结果仍保留且可跳至正式资产；用户删历史不能删除已入库资产副本。
- 依赖：V2-08/10/14。

### M5：质量安全与打包验收

**V2-18 全链路回归、CI、安装包与文档同步**
- 输出：迁移测试、接口 mock 测试、Provider 契约测试、实际 ComfyUI PoC、浏览器/Electron UI 冒烟、Windows NSIS 安装回归、README/交接更新。
- 验收：全部 V1 测试仍过，AI 失败/断网/磁盘满/重启/密钥错误和回收站等关键边界有回归；首次安装/升级不覆盖历史用户数据。
- 依赖：V2-01–17。

## 6. 测试策略

### 6.1 测试层级
- **单元**：能力 Schema 参数校验、来源枚举、默认模型优先级、Prompt CAS、目录推荐算法、角色/顺序保留。
- **服务集成**：FakeProvider/MockServer 实现视觉/LLM/生成/编辑/异步失败/重试；SQLite 临时库 + tempdir 文件事务。
- **契约 PoC**：对接用户允许的实际第三方兼容实例、OpenAI 官方、Gemini 官方、ComfyUI；测试结果留档，并注明版本和成功/失败能力（外部联网测试不能成为默认离线 CI 阻塞项）。
- **E2E UI**：现有 asset card/preview/batch、AI 设置、创作、历史和入库路径。
- **安装版**：Windows 10/11、后台 FastAPI 子进程、历史根目录权限、凭据存储、关停/重启后数据完整性。

### 6.3 验收门槛

- 按 AGENTS.md 执行 npm run typecheck、npm run build:web、项目 venv 的 pytest backend/tests；不能以“设计文档已完成”声称代码测试已通过。
- 所有新增端点必须有 Token/Host/Origin 测试；所有危险文件/Prompt 覆盖路径必须有未授权/并发/故障补偿测试。
- UX 不使用原生浏览器 confirm/alert/prompt；对 V1 Ctrl/Shift 多选、沉浸预览、回收站与原生文件拖出做回归。
- 创建新源码遵守 SRP 与 <800 行目标；新 Vue 组件/服务根据职责拆分。
- 验收所需的外部模型调用应先使用用户自有可测试 Provider/ComfyUI 实例，不在自动化中使用真实付费 API 反复跑大量数据。

## 7. 风险清单与先行动作

| 风险 | 严重度 | 规避 |
|---|---|---|
| 第三方 Compatible 生图/编辑不是标准协议 | 高 | V2-02 PoC 先行，独立 Adapter 和能力声明 |

| 图片编辑与文生图 API 混用 | 高 | 显式 mode + 双重 capability 校验 |
| AI 批量覆盖已有 Prompt | 高 | 逐项审核 + CAS + 明确确认 |
| 程序退出时远程任务仍执行 | 高 | external_handle、recovery_needed、禁止未知状态自动重试 |
| ComfyUI 工作流多样化与依赖失效 | 高 | API JSON 解析 + 参数显式映射 + 版本快照 + 真实 PoC |
| 凭据、私图与 Prompt 泄露 | 高 | 安全存储 + 后端调用 + host 约束 + 日志脱敏 |
| V1 数据迁移破坏现有资产 | 高 | DB 备份、兼容列新增、迁移幂等及回归 |
| AI UI 拉大 App.vue | 中 | 独立 features/ai，SRP、800 行上限 |
