## 文档维护规则

- 已确认产品决策只在对应版本 Spec 中记为“已确认”；尤其注意 V2 用户后续纠偏的结论，不能恢复被否决的旧方案。
- 技术架构与 UI 文档可以提出实现建议，但不能把未确认建议写成用户已作出的产品决定。
- 新增或变更产品决策后，首先更新 V2 Spec 和修订记录，再同步受影响的设计文档。
- V1 既有的存储、权限、删除、提示词单字段及 UI 操作语义，除非 V2 Spec 明确覆盖，应继续保持。
- 实现发现风险时优先通过 PoC、测试和工程方案解决；只有影响产品范围或数据安全时才重新向用户确认。
