# Ryan_DAM 二期 UI/UX 详细设计（V2）

- **版本**：v0.2 / 交互设计建议（2026-10-27）
- **产品基线**：[V2 Spec](./Ryan_DAM_Product_Spec_v2.md)
- **技术接口**：[V2 技术架构](./TECHNICAL_ARCHITECTURE_V2.md)
- **现有视觉规则**：[V1 UI/UX](./UI_UX_DESIGN_V1.md) + 根目录 AGENTS.md
- **说明**：下述布局、按钮位置、菜单名称、错误文案是待评审的**设计建议**；用户已确认的是 V2 Spec 的产品行为，而非本设计稿每一像素和控件。

**范围修订（㉒）**：ComfyUI 不在二期内接入，相关设置入口、Workflow 编辑器、图片执行模式及验收全部取消；等整个二期完成后再评估。

## 1. UX 目标与继承原则

1. **一套资产库，不建立第二套正式图库**。生成历史只是 AI 创作结果及任务记录空间，不能替代通用库/项目库。
2. **双入口**：资产库里就地反推、快速带图创作；复杂任务进入 AI 工作台（决策②）。
3. **意图显式**：用户选择图片生成 / 图片编辑，不按“有参考图”自动切换模式（⑨）。
4. **一次结果，一份正式 Prompt**：正式资产只有一份 prompt_text；区分提示词来源与资产来源（⑤）。
5. **生成≠入库**：所有结果永久留在历史中，用户确认单张/批量入库（⑥⑦）。
6. 延续 V1：浅色 Apple HIG、轻阴影、适量留白、44px 有效点击区、严禁 window.confirm/alert/prompt、全站统一 ConfirmDialog、受控键盘 Esc 和多选模式。
7. 高成本 AI 调用有明确“执行”动作；在发往第三方 API 之前，清楚呈现目标 Provider/模型，避免误用昂贵模型。

## 2. 主导航与信息架构

### 2.1 左侧导航建议

~~~text
Ryan_DAM
├─ 资产库
│  ├─ 通用资产库
│  └─ 项目资产库 / 项目...
├─ AI 创作
│  ├─ 图片创作（默认）
│  ├─ 生成历史
│  └─ 任务中心
├─ 标签 / 外部目录 / 回收站（延用原有导航）
└─ 设置
   ├─ 常规与托管存储（原有）
   └─ AI 配置
      ├─ Provider 连接
      ├─ 模型与能力
      ├─ 创作场景预设
      ├─ 图片反推模板
      └─ 默认模型与执行配置
~~~

**不建议**把“AI 生图结果”强制并入某个预设“AI 资产库文件夹”。正式入库时仍选择现有树形目录。

### 2.2 状态与路由

- 工作台界面建议拆成 ai/create、ai/history、ai/tasks 三个主视图或路由等价状态；不要求先引入大型路由框架。
- 从资产快捷入口跳转时携带内部安全状态（asset IDs、return_to、mode），而非序列化敏感 file_path。
- 切回资产库时保留原文件夹、搜索筛选、滚动与选中状态；工作台未提交 Prompt 可在本会话保留草稿。
- AI 任务在后台继续执行，任务中心显示角标与简短成功/失败提示；不抢占当前页面焦点。

## 3. 场景 A：AI Provider 设置

### 3.1 “添加连接”的优先顺序（确认需求）

**首先：自定义 OpenAI Compatible**；官方 **OpenAI** / **Google Gemini** 放在后置区域。不要将官方 API Key 输入作为默认唯一入口。

~~~text
设置 / AI 服务
  [+ 添加连接]
  ┌───────────────────────────────┐
  │ 推荐  自定义 OpenAI Compatible │
  │ 其他  OpenAI 官方 / Gemini 官方 │
  └───────────────────────────────┘

  我的连接
  [第三方接口 A] 已连接 视觉/文本/生图
  [第三方接口 B] 未验证 生图/编辑
~~~

### 3.2 Provider 表单字段

- 连接显示名（必填）；
- Provider 类型；Base URL（兼容 Provider 必填，可正确规范化）；API Key / 身份认证（需要时）；是否启用；
- **测试连接**与**按能力测试**为两个可区分操作；不会仅凭 /models 返回成功就显示“图片编辑可用”；
- 可添加多个模型配置：model_id、显示名、用途（文本、视觉、生成、编辑）、支持参数/数量限制及具体协议 Adapter；
- 连接列表展示各能力的“已验证/用户声明/不支持/测试失败”四类状态，减少假阳性；
- 添加完成后可配置“全局图片生成 GPT 模型”“默认视觉反推模型”“默认文本优化模型”。如果没有可用 GPT 配置，展示明确设置引导，不自动使用其它模型冒充全局默认。

### 3.3 默认模型选择器

- 当前手动指定 > 当前创作场景默认 > 全局该能力默认；
- 在模型下拉中可搜索 Provider/实例/Model ID，默认优先显示已验证支持当前任务类型的项；
- 用户切换模型后若 reference_count/尺寸/Seed 不兼容，在参数旁提示“当前模型不支持，需修改”；禁止静默提交非法参数。
- API Key 默认隐藏，修改/删除连接与清除密钥需要确认，页面不回显完整密钥。
- 非官方兼容 Provider 若不支持图片 API，需要明确显示“仅视觉/文本可用”，而非一概“连接成功”。

## 4. 场景 B：资产卡片与沉浸预览的 AI 入口

### 4.1 单张图片
- 图片卡片右上角/更多菜单中添加：**AI 反推提示词**、**使用此图创作**；在多选时仍优先执行选择，不允许新入口抢占卡片多选热区。
- 沉浸预览详情栏的提示词区域展示来源小标签：手动添加 / AI 反推 / 生图提示词 / 编辑提示词 / 未添加。
- 预览内“AI 反推”建议在右侧抽屉或尺寸足够的 modal 完成：选择反推模板 → 视觉模型 → 开始反推 → 结果可编辑/复制/可选 LLM 优化 → 保存。
- 已有 Prompt 的图显示原文与“覆盖后将替换当前唯一提示词”的危险说明；覆盖调用统一 ConfirmDialog；V1 的编辑/复制体验不变。
- “使用此图创作”带入当前图片作为参考图，并将工作台明确置为图片编辑**建议模式**，但要允许切换到图片生成（不硬推“参考图=编辑”）。

### 4.2 多选图片

- BatchActionBar 仅在选择的图片资产符合条件时显示“批量 AI 反推”；若混入非图片/缺失/回收站项，应清楚展示可分析数量及被排除数量，不悄悄全部失败。
- 批量反推弹窗：模板、视觉模型、预计处理数量、执行按钮；提交后关闭弹窗并在任务中心看到批量进度。
- 完成后进入“反推结果审核”列表，可单项/多项筛选、复制、编辑和批量保存。

## 5. 场景 C：单图与批量反推审核

### 5.1 反推结果侧栏

~~~text
[原图预览]  [提示词]
            来源：AI 反推（草稿，尚未保存）
            模板：角色特征反推  模型：XX
            [多行可编辑反推文本...]
            [复制] [按创作预设 AI 优化] [保存到资产]
~~~

- 按创作预设优化是**可选第二次调用**，必须显示将调用的文本模型。优化后仍可修改，并仅在“保存”时替换正式 Prompt。
- 反推目的是忠实描述可见图像，不暗示已恢复原始提示词。

### 5.2 批量结果审核

| 列 | 内容与行为 |
|---|---|
| 勾选 | 多选保存；可一键选择“当前没有 Prompt 的项” |
| 缩略图 | 图像及打开大图 |
| 资产名 | 原资产标识、状态 |
| 当前 Prompt 状态 | 无 / 手工 Prompt / AI Prompt；已有项标“需确认覆盖” |
| 反推结果 | 可展开全文、逐条编辑、复制 |
| 执行结果 | 成功 / 失败及错误提示 |
| 保存状态 | 待保存 / 已保存 / 覆盖冲突 / 跳过 |

- 点击“保存所选”前汇总：新填充 X 项、将覆盖 Y 项、失败 Z 项；已有提示词项必须明确确认；后台按项落库并反馈每一项结果。
- 如果反推期间另一个操作改写了原 Prompt，返回版本冲突，不强行覆盖；列表出现“已变更，请重新检查”状态。
- 不建立图片多个 Prompt 版本；待审稿属于反推任务的暂存结果，**不是**第二份资产 Prompt。

## 6. 场景 D：AI 图片创作工作台（主要屏幕）

### 6.1 推荐布局（以宽屏 1440×900 为基础）

~~~text
┌─────左侧项目/资产导航──────┬──────────── AI 图片创作 ─────────────┐
│                            │ [图片生成] [图片编辑]                │
│ 通用资产库                  │ 场景预设 [角色/服装/场景/自定义]        │
│ 项目资产库                  │ 模型 [GPT Image / 第三方兼容 / 官方]    │
│ AI 创作                    │                                        │
│   图片创作                  │ 参考图片（可多图，支持拖入/粘贴）         │
│   生成历史                  │ [图1 · 人物] [图2 · 服装] [+添加]        │
│   任务中心                  │                                        │
│                            │ 简单需求 / 最终提示词                  │
│                            │ [用户自然语言...                    ] │
│                            │ [AI 优化] [直接使用本段提示词]         │
│                            │ [LLM 按创作预设优化后的最终 Prompt... ] │
│                            │                                        │
│                            │ 生成参数（按模型动态展示）              │
│                            │ [比例] [数量] [质量] [高级参数...]     │
│                            │                         [生成图片]    │
│                            │                                        │
│                            │ 当前/最近结果：缩略图预览               │
│                            │ [重生成][变体][继续编辑][加入资产库]    │
└────────────────────────────┴────────────────────────────────────────┘
~~~

屏幕可在实现时拆分输入栏和结果栏，自适应较窄窗口，不固定上述 ASCII 几何。

### 6.2 操作优先级

1. 显式选择“图片生成”或“图片编辑”，模式不是由参考图数量推断。
2. 选创作预设，填充推荐模型/参数/Prompt 规则，但用户可以覆盖。
3. 参考图统一面板：从资产库、生成历史、本地文件选择、拖入、剪贴板粘贴；列表内拖动排序，允许每图标注人物/服装/场景/其他用途。
4. 参考图数量超出模型上限，阻止提交并指出超限项，**不自动丢掉**图片；本地文件在任务提交时转成受控不可变快照。
5. 提示词输入主要有两个层次：
   - **自然语言原始需求**（用户自由描述）
   - **最终 Prompt**（LLM 根据预设生成或用户直接输入，可编辑）
6. 点击“AI 优化”只产出文本，不直接开图；用户能直接跳过优化“直接生成”。
7. 点击“生成图片”才创建图片任务；按钮旁说明当前目标模型；任务被接收后输入表单仍可继续编辑下一次请求，旧任务 snapshot 不受影响。
8. 生成完成先进入结果预览/历史，**不会自动存入正式资产库**。

### 6.3 图片生成 vs 图片编辑

| 维度 | 图片生成 | 图片编辑 |
|---|---|---|
| 意图 | 生成全新图片，可带参考图 | 修改/延展已有图片 |
| 参考图 | 可选，数量按模型能力 | 至少需要主要编辑图片（工作流可有自身要求） |
| Prompt 引导 | 描述要生成的新内容 | 明确保留项与修改项 |
| 结果来源 | AI 生图 | AI 编辑 |
| 正式入库 Prompt | 实际生成 Prompt | 实际编辑 Prompt |

### 6.4 模型能力驱动参数区域

- 只有当 capability schema 允许时才显示并提交：比例/尺寸、质量、数量、Seed、参考图上限、透明背景等；
- 默认折叠高级项；必填参数必须可见；
- “9:16/16:9/3:4”等 UI 比例经 Adapter 转换为目标 API 实际支持尺寸。无法精确支持时需要明确提示，**不能声称实现了不存在的尺寸能力**；
- Provider 切换后不支持的参数给出可见解释和替代建议，而不是不可预测地失效。

## 7. 本期 UI 非范围说明：ComfyUI（㉒）

二期设置页**不显示 ComfyUI 可操作连接入口**，AI 工作台模型下拉**不显示 ComfyUI Workflow**，不制作 Workflow JSON 导入、节点映射与工作流预设界面，任务中心也无需特殊 ComfyUI 状态。

此前讨论的“API Workflow JSON + 显式输入/输出映射”的方向保留于 [V2 Spec 决策⑪](./Ryan_DAM_Product_Spec_v2.md)，但已被㉒延后。**二期全部完成后，用户若决定接入，重新设计并评审相关 UI**，不提前实现空白功能入口。

## 8. 场景 F：生成结果、历史与再次创作

### 8.1 生成结果卡片

- 缩略图/大图预览，来源 Provider/模型，生成时间，是否已入库；
- 主要按钮：**重新生成**、**生成变体**、**继续编辑**、**加入资产库**、**下载**；
- “继续编辑”以该结果作为新的主要编辑输入；上一轮参考图作为可选继承，避免自动再次提交不需要的素材。
- “重新生成”复用兼容配置，但提示结果不保证像素一致；“生成变体”带入配置供修改；任何再次创作产生新任务及新结果。

### 8.2 历史双视图

- **图片画廊（默认）**：全部结果时间倒序，用于快速找图；分页/懒加载/轻量缩略图，复用 V1 画廊技术。
- **任务分组**：按 task_id 聚合，在一组中显示多张结果、参数和输入参考图；完成但未入库与已入库结果均保留。
- 可筛选：Prompt/任务名、Provider/模型/Workflow、生成/编辑、日期、已入库/未入库、创作预设。
- 历史可独立打开大图；已入库结果提供跳转对应资产的入口；不能用“在图库中看到了生成结果”暗示已正式入库。
- 历史删除是**显式动作**，不自动按期限清理；删除前确认是否仍有正式资产副本，提示只影响历史而不删除正式资产（技术上用独立副本保障）。

### 8.3 任务中心（与历史职责不同）

- 任务中心：队列状态、执行状态、失败详情、取消请求、重试/打开结果、各 Provider 执行量；
- 生成历史：已经产生的、永久保留的图片结果、Prompt 与创作元数据；
- 状态只显示上游可验证的信息：有实际进度才显示百分比；没有则“执行中/已用时”；
- 重启桌面端后可恢复看已完成任务；未知上游状态显示“状态待确认”，不能自动重新生成造成费用风险。

## 9. 场景 G：结果选择性入库

1. 生成结果页选择 1 张或多张 → “加入资产库”。
2. 打开现有树形 TargetFolderDialog 的复用版本（不要新造不兼容文件夹选择器）。
3. 预选：单一图片资产来源 → 其原目录；跨多个项目或直接工作台 → 上次成功入库目录；初次 → 通用库默认位置。
4. 用户明确确认最终目标；若目录被删除或被锁定/不可用则提示重新选。
5. 执行复制校验、创建新 asset、写入唯一 prompt_text 与 asset_origin/prompt_origin 及生成任务关联。
6. 成功反馈“已加入 X 项 / 失败 Y 项”，生成历史仍保留所有图片，并可在历史卡片看到“已入库”标签。
7. 重复点击同一结果入库，默认提示已入库，不默默创建重复资产；如未来允许“再复制一份”需另作需求确认。
8. 不要求创建“AI 生图”等固定文件夹；支持沿用用户原目录组织。

## 10. 统一视觉与反馈规范

- 浅色、低饱和度、细边框、统一间距与圆角；避免高亮渐变 AI 营销风，内容图片本身是焦点。
- 主按钮层级：开始生成/保存入库一个 primary；AI 优化、直接生成、复制等为 secondary/outline，危险删除使用 danger。
- 不使用浏览器内置确认对话框；新增 AI 弹窗接入 ConfirmDialog 或基于一致组件封装的 Modal。
- 处理过程不锁死全屏；每个功能区域允许重试、切换浏览和关闭；错误优先用可理解的人类语言，例如“该兼容接口不支持图片编辑，当前仅可用于提示词反推”。
- 简易模型默认值配置：一处管理，工作台透明展示当前继承自场景还是全局，并允许一次性覆盖。
- 参考图预览需要区分保存到资产库/临时引用，禁止把历史图默默标成正式资产。
- 键盘语义：Esc 优先关闭最顶层弹窗、其次关闭大图、最后清多选；不得因工作台增加全局 Esc 监听破坏 V1。
- 主动云端调用图片时在连接详情/首次使用说明数据将发送到所选 Provider；不能把用户素材悄悄上报给其它服务。

## 11. 核心端到端交互状态与异常处理

| 场景 | 正常反馈 | 必须覆盖的异常 |
|---|---|---|
| Provider 测试 | 显示连通和对应能力状态 | Key 不正确、模型不存在、图片 API 未适配、限流 |
| AI 优化 | 可编辑最终 Prompt，明确目标 LLM | 提示词优化失败可保留原文并“直接生成” |
| 单图反推 | 结果可编辑/复制/保存 | 图片缺失、非图片、原 Prompt 已改变 |
| 批量反推 | 逐项展示结果、可选择性保存 | 局部失败、覆盖冲突、逐条重试 |
| 多参考图 | 显示顺序/角色/来源 | 超量、格式不符、源文件丢失 |
| 生成历史 | 全量留存、可检索 | 历史文件盘脱机、文件损坏、存储空间不足 |
| 手动入库 | 显示结果及目录、Prompt/来源 | 重复入库、文件名冲突、数据库提交失败 |
| 任务重启 | 已完成结果正常浏览 | 上游未知状态不能自行重新付费执行 |

## 13. UX 验收清单

- [ ] 从资产库单图进入反推并返回后，原资产浏览位置、目录、筛选仍在。
- [ ] 从资产卡片“使用此图创作”能带入该图作为参考，用户仍能切换生成/编辑模式。
- [ ] OpenAI Compatible 是第一推荐连接入口；能配置多个实例并可选模型。
- [ ] 用户自然语言 → AI 优化 → 可编辑最终 Prompt → 执行；也可直接跳过优化。
- [ ] 切换不同 Provider 时，不支持尺寸/参考图数的报错准确可理解。
- [ ] 批量反推待审核列表可以选择“无 Prompt 项”，不会覆盖原有 Prompt。
- [ ] 同一任务 4 个结果可选择只入库 2 个；历史 4 个继续显示。
- [ ] 生成历史有画廊/任务分组与多维搜索；任务中心独立显示运行中/失败任务。
- [ ] 再生成/变体/继续编辑继承相应配置且原历史图片不变。
- [ ] 与现有 ConfirmDialog、卡片多选、预览翻页、原生拖出交互均不冲突。
- [ ] 用户可区分“系统托管/外部关联”与“本地导入/AI 生图/AI 编辑”“手动提示词/AI 反推”三种不同属性。
