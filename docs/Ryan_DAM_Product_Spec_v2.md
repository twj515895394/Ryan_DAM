# Ryan_DAM 二期产品规格说明书（V2 Spec）

- **文档版本**：v0.2（需求事实基线 + 配套 V2 设计导航）
- **记录日期**：2026-10-27
- **文档性质**：产品需求 Spec；**不是**技术架构设计、UI 最终稿或开发排期
- **基线**：`main` 的 V1 产品与已交付功能；参见 [V1 Spec](./Ryan_DAM_Product_Spec_v1.md) 及 [交接记录](../.handoff/current.md)
- **二期工作分支**：`feat/phase2-ai-workbench`
- **状态说明**：决策①–㉑已完成讨论，其中⑱为**明确暂缓**；本文件区分“已确认需求”“实现建议”“待讨论问题”，不得将建议反向解释为用户批准。

> **产品主旨**：Ryan_DAM 从个人本地素材管理器发展为 **“资产管理 + AI 创作工作台”并重**的工具，闭环为：资产选择 / 自然语言需求 → 视觉反推或 LLM 提示词优化 → AI 图片生成/编辑 → 生成历史 → 手动挑选正式入库 → 再次创作。保留 V1 资产库的组织逻辑、安全边界与使用体验。

## 1. V1 基础与 V2 边界

### 1.1 不重做的一期基础

- Windows Electron + Vue 3/TypeScript/Vite + FastAPI + SQLite，项目库/通用库、多级文件夹、托管资产/外部目录关联。
- 画廊、媒体预览、搜索筛选、手工全局标签、批量操作、回收站、真实文件拖出。
- 图片/视频资产当前各有一个可为空的 `prompt_text` 完整多行提示词字段；必须兼容存量提示词，文本与换行不丢失。
- 现有 `source_type` 代表**存储形态**（例如 managed / external），**不能**用它记录“AI 生图/AI 编辑”等创作来源。
- 二期 AI 生成信息不能破坏 V1 的项目/通用库、外部文件只读以及安全删除等既定语义。

### 1.2 二期目前明确聚焦的领域

1. AI Provider / 模型 / ComfyUI 工作流接入与能力路由；
2. 单张和批量图片提示词反推、反推模板；
3. 自然语言 + LLM 按创作预设优化提示词；
4. 图片生成与图片编辑、参考图选择、创作场景预设；
5. 独立任务中心、永久生成历史、继续创作；
6. 正式资产选择性入库、单图单提示词、创作来源与生成任务追溯。

**暂缓/未确认**：AI 自动打标签明确暂缓；视频生成、视频反推、全文/语义检索、完整创作版本树等没有纳入本次已确认功能，不得根据构想擅自列为本期交付。

## 2. 决策记录（①–㉑）

| 编号 | 决策主题 | 已确认结论 |

| ⑦ | 未入库结果 | **B**：所有 AI 生成结果在独立生成历史中**永久保留**；不按时间自动清理，允许用户明确主动删除。 |
| ⑧ | 参考图输入 | **C**：统一参考图面板，来源含正式资产库、本地文件、拖拽、剪贴板粘贴、生成历史；支持多图、排序、移除与可选用途标注。临时图不强制入库。 |

| ⑩ | 生成执行 | **C**：独立任务中心 + 不同 Provider 的受控并发，非阻塞 UI，任务状态、失败与重试可追踪。 |

| ⑫ | 创作关系 | **B**：通过生成任务关联生成图片、参考素材、模型/参数/提示词，**不**建立全局复杂版本树；不扩大成跨项目通用资产的使用关系追踪。 |
| ⑬ | 正式入库目录 | **C**：按创作来源智能预选逻辑目录，入库时由用户确认或修改；复用既有目录树；不强制新增 AI 专属目录。 |
| ⑭ | 创作场景预设 | **C**：内置场景 + 用户自定义创作预设，覆盖创作模式、默认模型、提示词规范、比例及适配参数；用户仍可临时覆盖。 |
| ⑮ | 提示词创作流程 | **修订为**自然语言简单输入 → LLM 按创作预设规范润色/补足专业提示词 → 展示可修改最终文本 → 调用生图模型。**B**：默认提供 AI 优化，同时可选择“直接生成”跳过优化；已有专业 Prompt 不强制重写。 |
| ⑯ | 再次创作 | **C**：区分“重新生成”“生成变体”“继续编辑”，按意图智能继承上一轮提示词、参考图和兼容参数；新建任务，不覆盖历史结果。 |
| ⑰ | 生成历史 UI | **C**：默认图片画廊 + 可切换任务分组视图 + 搜索/多维筛选；与任务中心职责区分。 |
| ⑱ | AI 自动打标 | **暂缓，不做**：担心自动标签过于发散、近义词泛滥，保留 V1 手动标签；不开发自动/批量 AI 打标签及标签治理。 |
| ⑲ | 图片反推规模 | **B**：支持单张与批量图片反推；批量时每张独立分析，使用选定反推模板和视觉模型，纳入任务中心。 |
| ⑳ | 批量反推保存 | **C**：反推结果先预览，支持逐条修改/勾选/选择性保存；原有提示词必须经明确覆盖确认，不得静默覆盖。 |
| ㉑ | 反推与润色联动 | **B**：视觉反推结果可直接保存，也可**选择性**一键调用 LLM 按创作预设进一步优化；不强制双重调用。批量反推默认仅视觉分析。 |

> 历史纠偏（务必遵守）：⑤ 曾讨论“多提示词/版本”但用户明确否决；⑦ 推荐过定时清理但用户明确选永久；⑱ 推荐过自动打标签但用户明确暂停；⑮ 最初的“简单自由输入”被用户澄清为“由 LLM 依预设生成专业最终 Prompt”。**均以本表最终结论为准。**

## 3. 功能需求与可验收行为

### 3.1 AI Provider / 模型 / 工作流配置（对应③、⑪、⑭）

**配置入口与优先级**：
- “添加 Provider”入口优先显示 **OpenAI Compatible（自定义第三方 API）**，然后 ComfyUI；OpenAI/Gemini 等官方直连接入置于后面，仍然支持。
- 自定义连接支持命名、多实例、Base URL、凭据、模型 ID；相同服务类型可配置不同第三方接入地址。
- 维护模型对应的能力：视觉理解（反推）、文本 LLM（提示词优化）、图片生成、图片编辑；ComfyUI 的工作流作为特殊执行单元，不假定是普通单一模型。
- “API 能连通”≠“所有能力可调用”：能力应可配置/验证；不同兼容供应商的生图/编辑协议差异通过具体适配处理，不能仅靠聊天兼容推断支持。
- **默认规则**：图片生成使用可配置的 GPT 图像模型全局默认项；每个创作场景可设默认模型。此次临时选择 > 场景默认 > 全局默认。图片反推与提示词优化有各自可配置的视觉/文本模型默认值（具体默认型号尚待确定）。
- 凭据安全存储、日志脱敏、Provider 连通性/能力测试的技术方式在技术设计阶段细化，不能把 API Key 写进前端配置或生成历史的可见文本。

**ComfyUI**：
- 配置多个可连接的 ComfyUI 实例；导入、命名、更新和管理 API Workflow JSON。
- 自定义暴露的参数映射：如提示词、参考图、Seed、步骤、尺寸及输出节点；实际参数由所导入 Workflow 定义，不假定节点名称固定。
- Workflow 可以保存常用预设；从工作台调用时映射已绑定参数，校验依赖和必填项，再进入任务中心。
- 不新增类似 ComfyUI 的可视化节点编辑器。

**验收例**：两个不同 Base URL 的兼容 Provider 可共存；可分别用于图片反推和生图；切换场景默认模型不影响全局默认；导入 Workflow 可映射参考图并生成可回收的结果。

### 3.2 AI 图片提示词反推（④、⑤、⑲、⑳、㉑）

- 从资产卡片/沉浸预览执行**单图反推**；从多选工具栏执行**批量反推**。
- 系统预置通用画面、角色、服装、场景、摄影风格等反推模式（具体模板内容待设计），允许创建、编辑、复制用户自定义模板。
- 模板与视觉模型相互独立，可按模式指定默认模型；反推的目标是**对可观察图片内容作忠实描述**，不得声称恢复到原作者的真实 Prompt。
- 批量反推每张素材独立调用，进任务中心展示成功/失败；结果先进入待审核结果区。
- 单张/批量结果可复制、编辑、选择性保存；已存在提示词时必须经明确覆盖确认。批量结果允许快捷“只选择无提示词的项”。
- 反推之后可选择另行使用 LLM 创作预设优化；**不自动**增加一次 LLM 调用。
- 每个资产仍只有一份正式 `prompt_text`；保存反推内容时设置“AI 反推”来源标识，用户微调后仍可保留该反推来源。反推待审核稿存储于任务结果，不构成第二份正式资产提示词。

**验收例**：选择 30 张（20 无 Prompt + 10 有 Prompt），运行批量反推；保留 30 个分别可审核结果，先一键选择 20 张无 Prompt 保存，10 张原有 Prompt 未被修改，选中覆盖时显示明确确认。

### 3.3 LLM 按创作预设优化提示词（⑭、⑮、㉑）

- 用户可直接输入简单自然语言；选择创作预设后，调用配置的**文本 LLM** 将简单要求及模板规范组织为完整专业提示词。
- 用户可查看、编辑、复制、重新优化最终提示词；默认提供“AI 优化”流程，明确提供“直接生成”跳过选项。
- 已有完善专业 Prompt 可以直接提交，禁止擅自改写用户的角色身份、服装颜色、参考图编号和其他关键要求。
- 创作预设与反推模板**区分用途**：前者约束生成，后者约束视觉分析；允许复用底层模板管理，但用户概念不同。
- 生成任务保留用户初始输入、实际提交给图片模型的最终 Prompt 和所用预设的可追溯信息；正式入库的单份资产提示词为**实际提交的最终 Prompt**，不是用户初始草稿。
- 需要图片信息参与优化时，必须遵守所选文本/视觉模型的实际输入能力；不默认所有文本 LLM 都能读取图片。

**验收例**：输入“明代红衣侠客，院子，写实”并选择角色设计预设，可得到并编辑符合预设的专业 Prompt；点击“直接生成”则跳过 LLM 调用。

### 3.4 统一图片创作工作台（②、⑥、⑧、⑨、⑭、⑯）

- 左侧增加独立 AI 工作台入口；现有资产卡片/预览保留“AI 反推”“使用此图创作”等快捷入口，可带入资产/Prompt，简单反推不必切页面。
- 同一创作界面明确切换**图片生成** / **图片编辑**，不能仅依据“是否有参考图”判断任务意图。
- 支持统一参考图面板：来自正式资产库、生成历史、本地文件选择、拖入文件及粘贴图片；支持多图排序、移除、用途标注（人物/服装/场景等为可选语义，不假定模型 API 有原生角色槽位）。
- 临时参考图不要求正式入库；参与生成任务的输入须能在生成历史中追溯，防止用户移动源文件后复现信息丢失。
- 模型选择、尺寸/比例、数量、质量、Seed 等参数根据目标模型/Workflow 的**真实能力动态呈现**；不支持项不可直接发送，切换模型时应提示参数不兼容。
- 场景预设：内置角色设计、服装设计、场景设计等基础预设，允许用户自定义。预设初始化模式、默认模型、Prompt 规范、常用参数与参考图用途，不锁死用户调整。
- 生成后有结果预览，支持重新生成、生成变体、继续编辑、下载、选择性入库。不同操作按意图继承不同配置；任何新生成都创建新任务，绝不覆盖原有结果。
- 图片编辑产生**新图片**，不得原位替换已有正式资产。

### 3.5 AI 任务中心与执行（⑩、⑲）

- 支持不同 Provider/执行器的**受控并发**，排队、执行、成功、失败、取消和重试具有清晰状态；任务执行时用户可以继续正常使用资产库。
- 任务记录与实际使用的 Provider/模型/Workflow、参数、最终 Prompt、参考图和结果关联。
- 长任务可在应用重新打开后查看记录；运行中任务重连/恢复或未完成确认的准确语义由 API 能力和技术设计决定。不得盲目重复提交造成重复计费。
- “取消排队”与“请求终止进行中调用”必须区分；对无法真正取消的第三方 API 如实展示。
- 进度百分比仅在 Provider 返回可靠进度时展示，否则显示运行状态/耗时，不虚构百分比。
- 每个 Provider 的默认并发上限、超时重试和费用策略**尚未由用户确认具体值**，技术设计中再定。
- “任务成功”不等于“正式资产入库”。

### 3.6 永久生成历史（⑥、⑦、⑫、⑯、⑰）

- 所有生成结果**永久留存于独立的生成历史**，与正式资产库隔离；不会因工作台关闭、软件重启或保留期限到达而自动清理。
- 生成历史默认**图片画廊视图**，可切换**按任务分组**。支持按 Prompt/任务名称、模型或 Workflow、图片生成/编辑、时间、入库状态、创作预设检索/筛选（具体搜索体验在 UI 设计中细化）。
- 同一任务的所有结果留存；已入库项仍在历史中展示并标记对应入库状态，不因正式入库而消失。
- 历史结果可单张操作：预览、下载、重新生成、变体、继续编辑、加入资产库、用户主动删除。
- 历史中能查看生成模型、参数、实际 Prompt、参考图和任务时间；临时参考图需保留可追溯快照。
- 删除生成历史或关联资产时要避免误删仍被别处引用的文件，具体物理布局/引用计数/复制策略待技术设计。

### 3.7 正式入库与来源（⑤、⑥、⑫、⑬）

- 用户主动从生成结果中选单张或多张“加入资产库”，**不自动入库**；复用 V1 逻辑目录树并由用户确认或修改。
- 目录预选：从单一项目或通用库图片发起时优先原图片目录；独立工作台和多项目参考时优先上一次入库目录；无记录时预选通用库默认位置。所有预选都可更改，不强制建新目录。
- 新正式图片自动保存实际生成/编辑 Prompt，**每图一份**；记载 `asset_origin`（入库/创作来源）和 `prompt_origin`（手动、反推、生成、编辑等提示词来源），不得混淆 V1 的存储 `source_type`。
- 新入库图片通过生成任务 ID 追溯参考图及创作参数；**不**建立复杂跨项目素材引用图谱或完整版本树。
- 同一生成结果重复执行“加入资产库”的 UI 防误操作、重复语义、名称冲突及覆盖保护由设计阶段落实；不允许无提示覆盖其他原有资产。
- 生成历史中的永久留存义务不因入库而消失。

**典型来源区分**：

| 入库/操作场景 | 资产来源 | 提示词来源 |
|---|---|---|
| 本地导入，暂无 Prompt | 本地导入 | 无 |
| 本地导入，手动填写 Prompt | 本地导入 | 手动添加 |
| 本地导入，经视觉模型反推 Prompt | 本地导入 | AI 反推 |
| AI 文生图结果手动入库 | AI 生图 | 生图提示词 |
| AI 图片编辑结果手动入库 | AI 编辑 | 编辑提示词 |

**验收例**：项目目录 A 的参考图进入图片编辑并生成 4 张，仅选择 2 张入库；默认目标目录 A 可改为 B。两张新资产各自只有一份编辑 Prompt、正确来源、任务 ID；原资产未改动，4 张结果仍在生成历史。

### 3.8 手动标签保留与自动打标暂缓（⑱）

- 继续使用 V1 的全局手动标签与筛选能力。
- **本次不开发** AI 自动打标签、批量 AI 打标、自动标签字典治理。原因是标签同义词/粒度发散易破坏资产管理秩序。
- 如未来重新讨论，另行确立有限词表、审核机制与自动化策略；不得在当前开发计划中默认开启。

## 4. 用户流程（需求层）

### 流程 A：资产库 → 单图反推 → 保存
1. 打开资产图预览 → 触发 AI 反推 → 选择内置/自定义反推模板和视觉模型；
2. 得到忠实视觉描述；可编辑或选择 LLM 创作预设做**可选**进一步优化；
3. 保存到当前资产唯一 Prompt；如已有旧 Prompt，明确提示覆盖；记录 Prompt 来源。

### 流程 B：画廊多选 → 批量反推 → 选择性保存
1. 多选图片 → 选模板和视觉模型 → 创建后台批量任务；
2. 每张图独立得到待审核结果；失败单项可查看原因；
3. 可逐条编辑、筛选无 Prompt 的项、批量勾选并保存；已有 Prompt 先覆盖确认。

### 流程 C：自然语言 → LLM 优化 → 文生图 → 入库
1. 选创作场景、图片模型（默认 GPT）、参数 → 输入简单描述；
2. 默认提供 LLM 按预设优化并展示可修改最终 Prompt；可直接跳过；
3. 提交图像任务 → 生成结果保留于永久历史 → 预览/下载/继续创作；
4. 用户选择满意结果，确认或修改目标目录，正式入库并附上最终 Prompt、来源与任务关联。

### 流程 D：多参考图 → 编辑 / 变体 → 历史
1. 从资产库、历史、本地/剪贴板等加入多张参考图，标注用途；
2. 明确选图片生成或编辑模式；指定模型/Workflow，填写或优化 Prompt；
3. 后台受控执行；保留全部输出、实际参考图快照及参数；
4. 选择重新生成/生成变体/继续编辑时按动作恢复相应配置，并生成新任务。

### 流程 E：ComfyUI
1. 配置 ComfyUI 实例 → 导入 API Workflow → 映射输入/输出参数 → 保存预设；
2. 在统一工作台选择 Workflow 并填写暴露参数 → 提交任务；
3. 取回结果，写入永久历史，用户手动入库。

## 5. V1 兼容及数据约束

- V1 `assets.prompt_text` 存量数据必须保留；V2 **不**引入资产多 Prompt/Prompt 版本作为正式功能。
- `source_type` 继续只表达 managed/external 物理来源；`asset_origin`、`prompt_origin` 为**建议的新概念字段**，具体表名/枚举/迁移由后续技术设计决定。
- AI 任务与历史应具有可追溯的唯一标识，可对应多张生成结果；AI 入库资产应关联相应任务。其数据库表设计和文件去重/复制策略是**设计任务**，不是本 Spec 的固化实现。
- 不允许静默覆盖用户 Prompt、源资产或外部目录文件。
- 保持桌面客户端安全边界：限制任意文件路径和未经授权的本地 API 访问；与第三方服务通信的凭据不能暴露给不可信页面或保存在普通日志中。
- 不扩建全局跨项目资产使用关系，仅保留 AI 生成任务所需的输入来源关系。
