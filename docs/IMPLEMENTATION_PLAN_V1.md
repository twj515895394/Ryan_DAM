# Ryan_DAM V1 开发实施计划

- **版本**：v0.1
- **状态**：实施建议
- **产品基线**：[产品 Spec](./Ryan_DAM_Product_Spec_v1.md)
- **架构基线**：[技术架构设计](./TECHNICAL_ARCHITECTURE_V1.md)
- **UI 基线**：[UI/UX 设计规范](./UI_UX_DESIGN_V1.md)

## 1. 实施原则

- 先验证关键风险，再铺开业务功能。
- 每个阶段都产出可运行的软件，不一次性堆完所有模块。
- 数据安全与真实文件操作优先于视觉动效。
- 每阶段结束做功能验收和回归测试，再进入下一阶段。
- 不做 Spec 明确排除的 AI 功能、自动更新和复杂任务调度。

## 2. 阶段计划

### 阶段 0：技术验证与项目骨架

**目标：** 验证 Electron + Python 的桌面集成风险，并搭好可运行工程。

任务：
- 建立 Electron、Vue 3、TypeScript、Vite、Tailwind CSS、shadcn-vue 基础工程。
- 建立 FastAPI、SQLAlchemy、Alembic、Pydantic 后端工程。
- Electron 启动/关闭 Python 后端；实现健康检查与清晰的启动失败提示。
- 验证 Windows 原生拖出文件可拖入 Chrome 上传区域。
- 验证打包后的 Python 后端能独立启动，不依赖系统安装 Python。
- 建立日志和基础错误处理。

验收：
- Windows 上能启动独立客户端。
- Vue 页面能调用本机 FastAPI。
- 客户端退出时能正常关闭后端。
- PoC 证明从 Electron 卡片区域拖出的是真实文件。
- 关键验证失败时先解决技术方案，不进入大量 UI 开发。

### 阶段 1：数据模型与基础目录

**目标：** 形成可靠的本地数据基础。

任务：
- 配置 SQLite、SQLAlchemy、Alembic 和启动迁移。
- 建立 projects、folders、assets、tags、asset_tags、external_sources、import_jobs、import_job_items、app_settings 等基础表。
- 实现通用资产库和项目资产库的逻辑目录树。
- 实现默认托管目录设置，默认推荐 `D:\\Ryan_DAM\\assets`。
- 实现项目/文件夹基本创建、重命名、选择与目录校验。
- 建立资产路径、来源类型和状态字段的约束。

验收：
- 应用重启后数据库和目录状态保留。
- 通用资产与项目资产目录边界正确。
- 更改默认托管根目录不会让旧资产失效。
- 数据库迁移可以从空数据库初始化。

### 阶段 2：托管导入、任务面板与磁盘安全

**目标：** 稳定导入单文件、多选文件和文件夹。

任务：
- 实现文件/文件夹选择器与目标逻辑文件夹选择。
- 批量导入文件夹时保留子目录层级。
- 导入前检查预计空间，空间不足时提示用户。
- 实现哈希计算、重复检测、默认跳过和显式仍然导入。
- 实现 staging 临时文件、复制校验、原子落盘和失败清理。
- 实现持久化导入任务与任务明细。
- 显示进度、当前阶段、成功/跳过/失败数量。
- 实现失败原因查看与仅重试失败项。

验收：
- 导入期间 UI 不冻结。
- 相同内容重复导入符合默认跳过规则。
- 失败项可重试，成功项不会被重复处理。
- 空间不足/复制中断时不留下无法管理的半成品。
- 每条成功资产都有真实可访问的文件路径。

### 阶段 3：缩略图与媒体元数据

**目标：** 让用户通过视觉而不是文件名浏览素材。

任务：
- 图片缩略图生成和缓存。
- 使用 FFmpeg/ffprobe 提取视频代表帧、时长与尺寸。
- 读取音频时长与内嵌封面；无封面时使用音频卡片。
- 对 PDF、Office、文本类文件显示合适格式图标。
- 缩略图任务后台运行并记录状态。
- 缩略图失败回退到文件类型图标。

验收：
- 缩略图生成不阻塞导入和主界面。
- 失败不影响原始文件入库。
- 已生成缩略图可缓存复用。
- 视频时长、图片尺寸等信息准确显示。

### 阶段 4：画廊、搜索、预览与基础操作

**目标：** 完成资产库的主要日常工作流。

任务：
- 实现左侧导航、文件夹树、顶部工具栏和中央画廊。
- 实现网格/列表切换、分页或虚拟滚动、缩略图懒加载。
- 实现文件名、标签、文件夹名称/路径搜索及类型、大小、时间筛选。
- 实现沉浸式预览、侧边信息面板、上一项/下一项与关闭后恢复浏览位置。
- 实现图片预览、音视频播放、PDF/TXT/Markdown/JSON/CSV 基础预览。
- 实现单个托管资产重命名与逻辑目录移动。
- 实现标签 CRUD 和单个/批量标签管理。
- 实现回收站、恢复、永久删除和清空。

验收：
- 几千条资产时列表保持流畅，不能一次性渲染全部卡片。
- 搜索与筛选结果正确。
- 外部资产只读限制在 UI 和后端均生效。
- 文件移动/重命名后数据库与真实文件路径一致。
- 回收站行为符合产品 Spec。

### 阶段 5：外部目录、转托管与提示词

**目标：** 接入已有本地素材，并完善创作元数据。

任务：
- 关联外部目录并选择资产库目标文件夹。
- 扫描源目录并保留子目录层级。
- 手动重新扫描，识别新增、变更、删除/失效文件。
- 解除关联前显示影响数量；只清理仍为 external 的资产索引。
- 实现外部资产转托管：复制、校验、更新原记录，不创建重复资产。
- 实现图片/视频提示词添加、查看、复制、编辑和保存。
- 提示词原文完整保留换行与特殊字符。

验收：
- 关联外部目录不复制或修改源文件。
- 解除关联不删除源文件，已转托管资产继续保留。
- 转托管失败时仍是 external；成功后卡片就地更新。
- 提示词按钮状态符合“无提示词显示添加，有提示词显示查看”的规则。
- 复制内容与保存的提示词原文一致。

### 阶段 6：Electron 原生拖出、打包与质量验收

**目标：** 形成可以日常使用的 Windows 个人客户端。

任务：
- 将原生文件拖出整合到资产卡片和预览界面。
- 完成窗口尺寸/位置记忆与屏幕范围保护。
- 打包 Python 后端及所需媒体工具。
- 建立 Windows 安装包；不实现自动更新。
- 卸载时默认不自动删除用户数据。
- 完成核心数据安全、失败恢复、性能和 UI 回归测试。

验收：
- 从卡片和预览拖出的是真实原始文件，可拖入 Chrome 上传区域。
- 拖出不移动或修改源文件。
- 安装包在没有开发环境的 Windows 机器上可运行。
- 覆盖安装/重新安装不覆盖数据库与托管素材。
- 卸载不会静默删除用户素材。
- 完成 Spec 中已确认需求的核心验收清单。

## 3. 推荐优先级

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | Electron ↔ Python 启动、原生拖出 PoC、数据路径分离 | 提前发现影响整体架构的风险 |
| P0 | 导入、文件路径、SQLite、一致性处理 | 资产库基础与数据安全 |
| P1 | 缩略图、画廊、搜索、预览 | 决定日常使用体验 |
| P1 | 外部目录关联/扫描/转托管 | 解决存量素材接入 |
| P1 | 标签、批量操作、回收站、重命名 | 完成管理闭环 |
| P1 | 图片/视频提示词管理 | 服务 AI 创作素材场景 |
| P1 | Windows 打包和最终验收 | 形成可日常使用的客户端 |
| P2 | AI 标签、AI 反推提示词、自动更新 | 明确不属于 V1 |

## 4. Definition of Done

功能只有同时满足以下条件才视为完成：
- 满足产品 Spec 中对应的用户行为。
- 正常路径和失败路径均有反馈。
- 不破坏已有文件、资产记录、标签或提示词。
- 有自动化测试或可重复的验收步骤。
- UI 的加载、空状态、错误状态已覆盖。
- 关键文件操作在真实 Windows 环境中验证。
- 文档与实现行为一致。

## 5. 实施过程中的决策规则

- 普通技术细节由实现者根据 Spec 和架构文档选择稳妥方案，不逐项打断用户。
- 只有涉及产品范围变化、数据不可逆风险、明显性能/安全权衡或与已确认 Spec 冲突时，才重新向用户确认。
- 新发现的问题先检查能否由现有 Spec 与设计推导解决；不要为了“完整”无限增加需求。
