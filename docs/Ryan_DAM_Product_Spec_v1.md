## 1. 产品定位

Ryan_DAM 是面向自媒体创作者和 AI 视频生成用户的个人数字资产管理工具。主要解决本地图片、视频、音频、文档等素材分散、难查找、难预览和难复用的问题。

第一版优先把它做好为一个**轻量、快速、视觉体验精致的个人资产库**，不扩展为创作项目管理、制作流程编排或复杂的跨项目资产关系系统。

### 1.1 核心原则

1. **本地优先**：个人本地使用，资产文件与元数据主要保存在本机。
2. **系统托管为主，外部目录兼容**：新导入素材默认进入系统托管目录；已有目录可以只读索引。
3. **文件夹为主，标签为辅**：用户主要依靠自定义文件夹和子文件夹组织资产，全局标签、搜索和筛选用于辅助定位。
4. **先做好基础体验**：导入、缩略图、浏览、预览、搜索、批量管理和文件拖出优先于 AI 增强功能。
5. **保护原始素材**：外部目录默认只读；外部资产转托管采用复制，不改变原文件。
6. **不追踪创作使用关系**：不记录某项目用了哪些通用资产，不建立项目之间或项目与通用资产之间的引用关系。
7. **所有常见文件都能管理，但不要求所有格式都深度解析**：不支持内置预览的文件仍可以入库、检索、查看基础属性和下载/打开。
8. **界面响应快**：耗时文件操作、哈希计算与缩略图生成放在后台；大列表按需加载，避免阻塞主界面。

## 2. 用户与部署形态

- 目标用户：个人自媒体创作者、AI 图片/视频生成用户。
- 首发平台：Windows PC。
- 桌面客户端：Electron 独立窗口，提供 Windows 桌面启动和安装包。
- 前端使用 Web 技术构建，方便开发调试；已明确的首要交付形态是 Windows Electron 客户端。是否另行正式支持独立浏览器部署，仍待确认。
- 默认窗口尺寸约为 **1440 × 900 px**，首次启动居中；后续记住上次窗口尺寸、位置和最大化状态，并确保窗口不会超出可用屏幕范围。
- 最小窗口尺寸的具体数值尚未确认，开发时应保证资产网格和主要操作不会过度挤压。

## 3. 第一版功能范围

### 3.1 资产类型

第一版支持管理：
- 图片
- 视频
- 音频
- 文档及其他普通文件

对不支持深度预览的文件，仍需支持入库、基础属性、搜索/筛选、标签、下载或调用本地应用打开。

### 3.2 通用资产库与项目资产库

提供两个独立入口：

- **通用资产库**：直接按文件夹和子文件夹管理常用、可重复使用的素材。
- **项目资产库**：可以创建多个项目；每个项目拥有自己的文件夹和子文件夹。

两者不建立跨项目资产关联，不记录某项目引用/使用了哪些通用资产。复用是用户的使用习惯，不是系统需要维护的关系模型。

### 3.3 文件存储与外部目录

### 系统托管存储位置

- 首次启动时提供简洁的存储位置设置，预填推荐目录，用户可以选择其他磁盘或目录。
- 设置中的存储位置用于确定**新导入托管资产的默认存放位置**。
- 用户后续可以在设置中更改新资产的默认存储位置。
- 更改默认位置时，不自动迁移已有资产；已有资产继续保留在原位置，并且必须继续能够正常浏览、预览、搜索和管理。
- 因此，元数据需要记录每个托管资产的实际文件位置，不能假定所有历史资产永远位于当前默认目录。
- 默认推荐目录的最终路径、磁盘空间不足时的提示与处理策略仍待确认。

系统包含两类资产来源：

**系统托管资产**
- 文件复制/导入到 Ryan_DAM 管理的存储目录。
- 可以在资产库中执行支持的文件管理操作，包括重命名、移动、回收站删除等。
- 新导入素材默认使用系统托管模式。

**外部目录资产**
- 关联已有本地目录并建立资产索引，不复制原文件。
- 资产卡片和预览中显示明确的外部来源标识。
- 默认只读：可以浏览、预览、搜索、打标签；不直接移动、重命名或删除原始文件。
- 从资产库移除外部资产时，只删除资产索引，不删除磁盘上的原始文件。
- 支持手动刷新/重新扫描，识别新增、删除和变更文件。文件失效时明确标记为不可用，不静默消失。
- 第一版不做实时文件监控或定时扫描。

**外部资产转为系统托管资产**
- 提供“转为系统托管”操作。
- 采用**复制**方式将文件复制到系统托管目录；原始外部文件保留。
- 复制成功并完成必要校验后，才更新资产存储状态。
- 保留资产已有的标签、提示词等元数据。
- 失败时不得将资产标记为已转托管，也不得破坏源文件。

### 3.4 文件导入

支持：
- 拖拽文件导入
- 文件多选导入
- 本地文件夹批量导入
- 关联外部目录并扫描索引

文件夹批量导入默认**完整保留原有子目录和目录层级**，由用户选择导入目标位置，不将所有文件扁平化混放。

#### 重复文件检测

- 对导入文件与资产库已有文件进行内容重复检测，以文件内容哈希为主要依据，而不是仅比较文件名。
- 检测到内容完全相同的文件时提示用户，默认跳过。
- 允许用户选择仍然导入。
- 不自动删除、不自动合并已有资产。
- 哈希等耗时计算应在后台执行；大文件处理不能阻塞 UI。

#### 导入任务面板

显示：
- 总体导入进度
- 当前处理阶段
- 成功、跳过、失败数量
- 失败原因
- 重试失败项目的入口

重试时不重复处理已经成功完成的项目。缩略图生成失败不应导致原始文件导入失败。第一版不做完整任务调度中心，不要求暂停、恢复、并发编排或复杂历史日志。

### 3.5 文件夹与标签

- 文件夹和子文件夹是主要组织方式。
- 用户可自定义文件夹结构。
- 通用资产库和每个项目的目录边界清晰。
- 标签采用**全局统一标签体系**，同一个标签可应用于任意文件夹中的资产。
- 支持创建、编辑、删除标签，以及给单个或多个资产添加/移除标签。
- 标签支持全库搜索，也支持在当前文件夹范围内筛选。
- 第一版只做手动标签，不实现 AI 自动标签。数据结构可为未来的标签来源扩展留出空间，但不提前实现 AI 推理。

### 3.6 搜索、筛选与排序

第一版支持基础资产搜索：
- 关键词匹配文件名
- 标签
- 文件夹名称和路径
- 按文件类型筛选
- 按文件大小筛选
- 按修改时间筛选
- 对结果排序

第一版不做文档全文搜索、AI 语义搜索或向量检索。

### 3.7 浏览与卡片

- 默认使用缩略图网格，可切换列表视图。
- 不同文件类型采用合适的缩略图或文件卡片。
- 精致信息卡片显示：缩略图、文件名、与类型相关的信息、少量标签。
- 例如视频显示时长，音频显示时长，文档显示格式/大小等适当信息。
- 更多操作按钮在卡片悬停时出现，避免常态界面拥挤。
- 外部资产必须显示来源标识。
- 网格列数随窗口宽度自适应；缩略图按需加载。

### 3.8 缩略图

在后台生成并缓存缩略图：
- 图片：生成图片缩略图。
- 视频：提取代表帧并显示视频时长。
- 音频：优先读取内嵌封面；没有封面时使用音频卡片。
- 文档：使用对应格式图标。
- 生成失败：回退到文件类型图标，不影响资产正常管理。
- 第一版不做视频动态缩略图、多帧选择或音频波形分析。

### 3.9 预览

- 采用沉浸式预览层 + 侧边信息面板。
- 关闭预览后恢复原来的浏览位置与滚动位置。
- 支持上一项、下一项及常用资产管理操作。
- 图片、视频、音频使用对应的媒体预览方式。
- PDF、TXT、Markdown、JSON、CSV 等常用基础格式提供内置预览。
- DOC/DOCX、XLS/XLSX、PPT/PPTX 等 Office 文件第一版不做在线预览，但支持入库、搜索、查看基础属性和下载/调用本地应用打开。
- 不要求第一版对所有专业创作文件做深度解析。

### 3.10 图片与视频提示词

图片和视频资产各自支持一个可为空的**完整多行提示词字段**。它属于资产元数据，不写入或修改原始媒体文件。

交互规则：
- 没有提示词时，显示“添加提示词”，不显示“查看提示词”。
- 已有提示词时，显示“查看提示词”。
- 入口位于卡片悬停操作区和沉浸式预览界面。
- 查看弹窗显示完整提示词，并提供“复制提示词”按钮。
- 弹窗支持进入编辑、保存修改。
- 保存和复制应保留原始文本、换行和特殊字符，不擅自改写提示词。
- 不强制拆分正向提示词、负向提示词或绑定特定模型格式。
- AI 反推/生成提示词本期不做，作为后续增强方向。

### 3.11 批量管理与重命名

支持多选资产，并执行：
- 批量添加标签
- 批量移除标签
- 批量移动到文件夹
- 批量删除

支持重命名单个系统托管资产：
- 默认保留文件扩展名。
- 检查同一目标目录下的命名冲突。
- 同步更新资产索引和相关缓存引用。
- 外部目录资产保持只读。
- 第一版不做批量重命名。

### 3.12 回收站与删除安全

- 系统托管资产删除后进入资产库回收站。
- 支持恢复、永久删除和清空回收站。
- 永久删除和清空操作需明确提示风险。
- 回收站中的托管文件仍占用磁盘空间，直到永久删除。
- 外部目录资产移除时只移除索引，不删除原文件。
- 批量删除需确认，并反馈成功/失败结果。

### 3.13 桌面原生文件拖出

这是 Windows Electron 客户端的核心验收能力。

- 支持从资产卡片和沉浸式预览界面拖出真实文件。
- 可以拖到 Chrome 等浏览器的上传区域，或其他支持文件拖放的应用。
- 系统托管资产拖出实际托管文件；外部资产拖出原始文件。
- 拖出不移动、不删除、不修改源文件。
- 拖出交互不得明显干扰卡片点击预览和多选操作。
- 不以缩略图、网页 URL 或临时预览图代替原始文件。
- 第一版支持图片、视频、音频和文档等原始文件拖出。

## 4. UI 与交互规范

### 4.1 视觉方向

采用 Apple 风格的明亮、克制、精致设计：
- 浅色背景、柔和灰阶、清晰排版和细腻留白。
- 使用少量强调色，避免花哨装饰和普通后台模板感。
- 重点突出资产内容本身。
- 保持统一的间距、圆角、边框、悬停、选中和反馈状态。

### 4.2 主界面布局

- 左侧：通用资产库、项目资产库、文件夹树及必要入口。
- 顶部：全局搜索、筛选/排序、视图切换、导入等常用操作。
- 中央：资产画廊。
- 详细属性放在沉浸式预览层，不长期占用主网格空间。
- 左侧导航可折叠。
- 默认网格，可切换列表。

### 4.3 响应式适配

- 桌面端优先，充分利用 PC 宽屏。
- 平板适配主要管理功能。
- 手机优先保证基础浏览与预览。
- 缩略图按需加载，长列表考虑虚拟滚动，避免一次渲染所有资产。

### 4.4 Electron 窗口

- 首次启动约 1440 × 900 px，居中显示。
- 后续记住上次窗口尺寸、位置和最大化状态。
- 恢复时检查当前屏幕可用区域，避免窗口完全或部分跑出屏幕。
- 最小尺寸数值尚待确认。

## 5. 技术选型

### 5.1 已确认技术栈

| 层级 | 选择 |
|---|---|
| 桌面容器 | Electron |
| 前端 | Vue 3 + TypeScript + Vite |
| 样式 | Tailwind CSS |
| UI 组件 | shadcn-vue |
| 后端 | Python + FastAPI |
| 数据模型/ORM | SQLAlchemy |
| 数据库迁移 | Alembic |
| 数据校验 | Pydantic |
| 元数据数据库 | SQLite |
| 首发平台 | Windows |

### 5.2 文件与元数据职责

- SQLite 保存资产元数据、文件夹、项目、全局标签、提示词、存储来源、哈希、缩略图状态及导入任务结果等信息。
- 原始媒体文件保存在系统托管目录或用户指定的外部目录。
- 缩略图和预览缓存单独存放，便于重建与清理。
- 数据库不保存大型媒体文件本体。
- Python 后端通过本地 API 为前端提供资产管理能力。
- Electron 负责桌面窗口与操作系统集成，特别是原生文件拖出。

### 5.3 性能与稳定性要求

- 文件扫描、复制、哈希、缩略图生成等耗时工作不能阻塞 UI 或 API 请求。
- 缩略图和媒体元数据应缓存，文件未变化时尽量避免重复计算。
- 大文件导入应提供进度和失败原因。
- 缩略图失败不能导致资产不可管理。
- 外部目录不可用时应标记资产状态，不应静默删除记录。
- 对文件操作失败提供可理解的错误信息，避免只记录在控制台。

> 后续实现时应单独明确 Electron 与 Python 子进程的打包、启动/退出、端口占用处理，以及本地 API 的访问安全边界；这些是工程设计事项，当前尚未逐项确认。

| 25 | 缩略图 | 图片生成缩略图；视频提取代表帧并显示时长；音频优先内嵌封面；文档使用类型图标；后台生成并缓存。 |
| 26 | 原生拖出文件 | 从卡片和预览拖出真实原始文件；不修改源文件。 |
| 27 | 文件夹导入结构 | 默认保留原有子目录与层级，用户选择目标位置。 |
| 28 | 删除 | 系统托管资产使用回收站；外部资产移除只删除索引，不删除源文件。 |
| 29 | AI 自动标签 | 第一版只做手动标签，AI 自动打标签暂不实现。 |
| 30 | 提示词入口 | 图片/视频卡片悬停区和预览界面均提供添加或查看提示词入口。 |
| 31 | 提示词结构 | 图片/视频各自一个完整多行提示词字段；支持查看、复制、编辑和保存；AI 反推暂不做。 |
| 32 | 导入任务反馈 | 显示总体进度、阶段、成功/跳过/失败数量；查看失败原因并重试失败项目。 |
| 33 | 重命名 | 支持重命名单个系统托管资产，默认保留扩展名；外部资产只读，不做批量重命名。 |
| 34 | 系统托管存储位置 | 首次启动可选择存储位置并预填推荐目录；设置中可修改新资产的默认存储位置；修改时不自动迁移已有资产，旧资产继续可用。 |

## 7. 明确不纳入第一版的功能

- AI 自动标签与本地/云端模型推理。
- AI 反推图片或视频提示词。
- 文档全文搜索、AI 语义搜索和向量检索。
- Office 在线预览。
- PSD、AI 等专业设计源文件的深度解析。
- 视频动态缩略图、多帧选择、音频波形分析。
- 实时监听或定时扫描外部目录。
- 跨项目资产引用/使用关系。
- 批量重命名、格式转换、复杂批处理规则。
- 完整的任务调度中心（暂停、恢复、并发编排等）。
- 多用户、云端协作和服务端部署能力（当前没有此类需求确认）。
