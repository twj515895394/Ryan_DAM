## 1. 本次会话完成的修复与重构清单

### 1.1 Provider 与模型列表自动探测自愈（Local Gateway /models Healing）
- **问题现象**：用户在配置第三方 API 提供商（如 `http://127.0.0.1:8000`）时，无论 `base_url` 是否包含 `/v1`，测试连接或获取模型列表均易受端点路径差异（`/v1/models` vs `/models`）影响。
- **修复方案**：
  - 后端适配器增强双向回退探测逻辑，针对本地或特定代理网关自动适配尾部 `/v1` 路径差异；
  - Windows DPAPI 加密存储凭据保持安全闭环，接口脱敏显示；
  - 前端添加模型配置弹窗支持直接从 `/models` 接口获取已部署模型，展示名称根据 `model_id` 自动智能填充。

### 1.2 全站 Anti-Slop 视觉规范与 Apple HIG 组件替换
- **问题现象**：原二期表单（如生图工作台、反推设置、模型配置）中存在少量操作系统原生 `<select>` 标签与 Windows 默认粗灰滚动条，视觉廉价且无搜索能力。
- **修复方案**：
  - 全面引入并替换为 `apps/web/src/components/AppleSelect.vue`，具备毛玻璃背景（`backdrop-blur-xl`）、`shadow-2xl`、类别状态徽标（badge/badgeColor）、选中间隙 checkmark、自适应上下翻折和快速过滤搜索能力；
  - 全局注入无侵入微型悬浮滚动条规范（`scrollbar-width: thin`，透明轨道，6px 圆角半透明悬浮滑块），彻底杜绝原生粗灰色滚动条破坏设计美感。

### 1.3 反推模板与创作预设可视化管理 GUI
- **问题现象**：内置的视觉反推模板与风格预设此前写死在常量中，用户缺少直观查看、增删改查及启用/禁用的配置入口。
- **修复方案**：
  - 新增 `apps/web/src/components/AiTemplateSettings.vue`（629 行，严格遵守 SRP 与 ≤800 行限制）；
  - 在 `SettingsDialog.vue` 中无缝集成「反推模板管理」与「创作风格预设」独立标签页，支持预设/自定义标识过滤、即时创建、就地编辑与二次确认删除。

### 1.4 AI 视觉反推弹窗有内容后取消/关闭失效修复（Critical Bug Fix）
- **问题现象**：在单图视觉反推弹窗（`AiReverseModal.vue`）中，反推生成提示词文本后，点击右上角关闭按钮（X）及底部“取消”按钮没有任何反应。
- **根本原因**：
  1. **弹窗容器视口撑爆（Viewport Overflow）**：反推前高度适中，反推后大段草稿文本渲染使未受限的平铺式弹窗纵向急剧拉长，底部操作栏被顶出屏幕下方可视区域；
  2. **事件捕获丢失**：关闭按钮内嵌裸 SVG 拦截了点击，且缺少 `@click.stop` 和显式 `type="button"`；
  3. **层级倒挂（Z-Index Inversion）**：`AiReverseModal` 处于 `z-[60]`，而底层通用的覆盖确认框 `ConfirmDialog` 设定在 `z-50`，导致覆盖弹窗被遮挡在下层；
  4. **缺少键盘流支持**：缺乏全局 <kbd>Esc</kbd> 监听拦截。
- **重构方案**：
  - 弹窗重构为**「三段式固定+滚动」标准容器**（`max-h-[90vh] flex flex-col overflow-hidden`）：
    - **固定头部（Fixed Header）**：`shrink-0 border-b`，关闭按钮带 `pointer-events-none` 与 `@click.stop="handleClose"`；
    - **独立滚动体（Scrollable Body）**：`flex-1 overflow-y-auto px-6 py-5`，参数选择与长文本框包裹在内部独立滚动；
    - **固定底部（Fixed Footer）**：`shrink-0 border-t bg-canvas/40 px-6 py-3.5`，取消与保存按钮固定置底，始终清晰可点；
  - 将 `ConfirmDialog.vue` 层级提升至 `z-[70]`；
  - 挂载全局 <kbd>Esc</kbd> 快捷键监听与事件拦截。

## 2. 避免后续 Agent 踩坑的硬性规范约束

为了杜绝后续参与开发的 AI Agent 重蹈覆辙，以下规则已白纸黑字固化到项目根目录 `AGENTS.md`（§2.5 与 §2.6）及长期记忆索引 `custom-dialog-design-style.md` 中：

### 2.1 弹窗与浮层容器强制规范（Anti-Overflow 强制防撑爆）
1. ❌ **严禁使用平铺式未受限容器**：绝不允许编写外层没有最大高度限制（`max-h`）、没有内部滚动区域的弹窗。任何含有 AI 生成文本、列表或动态表单的弹窗，内容膨胀后必将撑爆视口。
2. ✅ **必须统一采用三段式固定+滚动架构**：
   - 外层：`max-h-[90vh]`（或 `max-h-[85vh]`），配合 `flex flex-col rounded-2xl overflow-hidden`；
   - 头部：`shrink-0 border-b`，固定吸顶；关闭按钮声明 `type="button"`，图标加 `pointer-events-none`，绑定 `@click.stop`；
   - 身体：`flex-1 overflow-y-auto`，所有输入项和生成结果必须放在此处；
   - 底部：`shrink-0 border-t`，固定吸底，放置取消与确认动作按钮；
3. ✅ **必须绑定 <kbd>Esc</kbd> 物理按键安全退出**：
   - 使用 `window.addEventListener("keydown", onKeydown)`，在 `open` 时监听并在卸载/关闭时清理；
   - 必须执行 `e.preventDefault(); e.stopPropagation();`，避免连带关闭父级抽屉或全屏预览；
4. ✅ **严格遵守 Z-Index 层叠分级体系**：
   - 底层页面：`z-0` ~ `z-30`
   - 全屏资产预览（`AssetPreview.vue`）：`z-40`
   - 普通业务弹窗/工作台（`AiWorkbenchModal` / `PromptModal` / `SettingsDialog`）：`z-50` ~ `z-[55]`
   - 嵌套子业务弹窗（如预览内唤起的 `AiReverseModal`）：`z-[60]`
   - 全局二次确认与破坏性阻断弹窗（`ConfirmDialog.vue`）：`z-[70]`。

### 2.2 表单控件与 Anti-Slop 约束
1. ❌ **禁止在任何业务代码中裸写 `<select>`**：所有下拉选择器一律使用 `apps/web/src/components/AppleSelect.vue`。
2. ❌ **禁止原生粗灰直角滚动条**：所有滚动容器依赖全局样式的悬浮细滚动条。
3. ❌ **禁止 `window.alert()` / `window.confirm()`**：所有弹窗统一走 `ConfirmDialog.vue`。
