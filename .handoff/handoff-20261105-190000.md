## 2. 主要意图与架构决策

1. **批量操作栏裁切修复**：
   - **现象**：多选资产后，点击底部批量栏的“移动到…”、“加标签”等按钮，弹出的目录/标签面板无法点选。
   - **根因**：批量栏横向滚动容器为了防止按钮换行变形，之前添加了 `overflow-x-auto`，触发 CSS 规范将垂直方向也计算为 `overflow-y: auto`，导致向上弹出的绝对定位浮层被父容器直接裁剪且点击事件穿透。
   - **解法**：将上弹面板通过 Vue `<Teleport to="body">` 提升至顶层容器，采用 `fixed` 锚定在批量栏上方，并注册捕获相位的 Esc 与外部点击关闭监听器。
2. **局域网免鉴权开放接口（Open API）**：
   - **用户决策**：个人局域网内使用，无需鉴权负担；支持跨机/其他项目直接调用生图和图生图能力；模型跟随项目配置的默认模型；生成结果默认自动入库到「AI 生成」目录。
   - **安全边界设计**：
     - 仅对 `/api/v1/open` 路由前缀免除 Host 白名单、Origin 检查和 `X-Ryan-DAM-Token` 令牌校验；
     - 本应用自身管理资产、目录、设置等核心接口依然严格受到本地回环与 Token 守卫保护；
     - CORS 针对任意 http(s) 来源放行，支持局域网内其他设备通过 Web 页面直接调用；
     - 监听绑定 `0.0.0.0:8765`（支持 `RYAN_DAM_LAN_PORT` 覆盖，被占用自动降级随机端口），并在数据目录自动维护 `endpoint.json` 服务发现文件（记录端口、局域网 IP 与接口列表），进程退出时自动清理。
3. **生图链路与自动入库**：
   - 复用现有 `submit_image_generation` 引擎，外部调用享受完全一致的模型适配与调度重试机制；
   - 调度器在任务执行 `succeeded` 终态后，自动触发 `auto_import_task_results`，将产物原子入库至「AI 生成」目录，同时生成历史在 `ai_results` 中永久留存；
   - 修复了模型默认绑定 scene 存储为 `global` 而解析查 `general` 的历史不一致缺陷，兼容两类并以 `global` 为准。
4. **取图与直连 content_url**：
   - 任务响应不仅包含相对路径 `content_path`，还直接给出完整直连的 `content_url`，外部项目无需做任何 URL 拼接；
   - 开放路由在服务端挂载 `/open/` 与 `/api/v1/open/` 兼容别名，杜绝客户端错误拼接前缀导致的 404。

## 3. 踩坑与经验总结（Gotchas）

1. **content_path 拼接重复导致 404**：
   - 后端原返回 `content_path: "/api/v1/open/images/results/.../content"`；外部项目配置了 `BASE="http://ip:port/api/v1/open"` 后若直接执行 `BASE + content_path` 会出现双重 `/api/v1/open`。已通过增加直连 `content_url` 及服务端别名路由彻底化解。
2. **模型能力 capabilities 结构解析**：
   - 前端与服务层实际存储的是字典 `{"supported": bool}`，直接使用真值检查 `if p.capabilities.get(key)` 会将 `{"supported": false}` 误判为支持。必须使用 `isinstance(dict)` 提取 `.get("supported")`。
3. **Electron 开发模式需重启后端**：
   - `npm run dev` 模式下仅 Vite 前端支持 HMR，Python 后端作为子进程常驻运行，后端的端口监听与新路由变更必须完全重启桌面端方可生效。
