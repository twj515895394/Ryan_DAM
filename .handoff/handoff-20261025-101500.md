## 2. 待处理问题记录（下个会话继续处理）

### 待处理问题 1：删除目录支持级联删除文件夹及内部文件（加确认弹窗）
- **现象与痛点**：目前删除非空目录时，后端抛出 `409 folder_not_empty`（提示“目录仍包含 X 个资产，删除目录前请先移走资产”），前端强制用户必须先进入子目录逐一删除文件才能删除文件夹，操作极其繁琐。
- **目标方案**：
  - 后端：`folder_service.delete_folder` 提供参数（或默认支持递归级联删除），将目标目录及其所有子孙目录下的资产一并移入回收站（外部资产删除索引），并级联删除目录记录。
  - 前端：使用统一的 Apple HIG `ConfirmDialog`，检测到该目录下有文件或子目录时，在弹窗说明中明确显示将要一并移入回收站的资产数量与子目录信息，用户点击“确认删除”后一次性级联删除。

### 待处理问题 2：回收站资产支持预览查看功能（图片、视频、音频、文档）
- **现象与痛点**：当前回收站（`TrashView.vue`）为简单表格列表，用户想要确认删除了什么内容时无法点击查看预览，体验不完整。
- **目标方案**：
  - 后端：放行回收站已删除资产的内容流读取与缩略图请求（目前 `GET /api/v1/assets/{asset_id}/content` 和 `thumbnail` 限制了 `asset.status == "active"`，已 trashed 资产会被拒绝 404），支持查看 trashed 文件的实体内容。
  - 前端：`TrashView.vue` 表格行支持点击打开预览弹窗（或复用/精简版 `AssetPreview.vue`），使用户在回收站中也能清楚核对图片、视频、音频、文档内容后再决定是“恢复”还是“永久删除”。

## 3. 核心规范与约束速查备忘

- **Python 环境**：必须走 `.venv/Scripts/python.exe`，禁止全局 Python。
- **前端开发端口**：严格使用 `http://127.0.0.1:5173`（后端 CORS 白名单硬编码）。
- **设计规范（Apple HIG & Anti-Slop）**：
  - 严禁原生 `window.confirm` / `alert`，统一使用 `ConfirmDialog.vue`。
  - 资产多选遵循 44×44px 热区与双模交互。
- **架构规范**：
  - 遵循单一职责（SRP），单文件代码行数尽量不超过 800 行（超限及时抽离组件/服务）。
- **三项交付验证**：
  1. `npm run typecheck`
  2. `npm run build:web`
  3. `.venv/Scripts/python.exe -m pytest backend/tests`
