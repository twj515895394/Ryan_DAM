## 1. 用户需求（原话）

> 「代码类文件可以像文本一样预览吗。还有现在对列表预览显示，这个有缓存机制吗 加快列表图片和视频的缩略图显示？」
> 附截图：外部资产 `qc_case.py` 沉浸预览落到「浏览器无法直接播放该格式」兜底，右侧信息面板显示 类型:文件 / 来源:外部链接。

## 2. 现状诊断（回答第二问）

- **后端缩略图早已有盘缓存**（票 7 遗留体系）：`thumbnail_service.py` 后台 worker 生成 512px JPEG 存 `<data>/cache/thumbnails/<id>.jpg`，sidecar `<id>.json` 记 size+mtime_ns 指纹，源文件变更才重生成；`GET /thumbnail` 直接 FileResponse（Starlette 自带 Last-Modified/ETag 条件缓存），miss 返 404 `thumbnail_unavailable`。
- **前端此前没有任何缓存**：`AssetCard.vue` / `TrashRowThumb.vue` 每次挂载都带 token 重新 fetch blob、卸载即 revokeObjectURL——滚动虚拟化、目录切换、回收站往返都对同一资产重复请求。这就是用户看到「列表缩略图慢」的实际缺口。

## 3. 设计决策

- **代码文件归类（后端）**：`import_service.py` 新增 `CODE_EXTS`（py/js/ts/tsx/jsx/vue/svelte/html/css/scss/less/yml/yaml/xml/toml/ini/cfg/conf/properties/sh/bash/zsh/bat/cmd/ps1/sql/java/c/h/cpp/hpp/cc/cs/go/rs/rb/php/swift/kt/lua/pl/r/gradle/proto/graphql/log，共 47 个），并入 `DOC_EXTS` → 新导入/外扫的 `.py` 等注册为 `document`（类型显示「文档」）。无新增 asset_type，零迁移。
- **前端文本预览**：`AssetPreview.vue` 增加 `CODE_PREVIEW_EXTS`（与后端清单一致，无前导点）；`docKind` 重构为 document 分支照旧 + **存量 `other` 资产按扩展名回退 text**（用户现有 qc_case.py 已存为 other，重扫不会改分类——这是存量数据生效的唯一途径）；`textPreview` 新增 `code` kind → 模板 `font-mono text-xs leading-6 [tab-size:4] whitespace-pre-wrap break-all` 等宽卡片，保留缩进、无语法高亮依赖（Anti-Slop 简约）。
- **缩略图共享缓存（前端）**：新 composable `useThumbnailObjectUrl`——模块级 `Map` LRU（上限 240 条 ≈ 最坏 ~30MB）长期持有 object URL，重挂载卡片直接复用、卸载**绝不 revoke**；`thumbnail_status=failed` 记负结果不再反复 404，状态离开 failed 自动清除；LRU 逐出才 revoke；迟到成功结果也入缓存。AssetCard/TrashRowThumb 各自的加载逻辑整体删除，收敛到该 composable（单一职责）。
- **已知取舍（记录在 composable 头注释）**：源文件被替换且后端重生成缩略图后，缓存条目会显示旧图直到 LRU 逐出；512px 列表预览场景可接受。后端未加显式 Cache-Control（避免陈旧内容，且前端内存缓存已消除重复请求）。

## 6. codereview 结论

- 0 致命、0 需修。核实点：`wantText = docKind === "text"` 自动覆盖 code kind（fetchContentText + 2MB 截断共用）；`other` 分支仅文本/代码扩展可预览（zip 等仍走兜底）；composable `onScopeDispose` 只作废在途请求不误伤缓存；LRU 逐出 revoke 不会打到屏上卡片（同屏挂载数 << 240 上限）；前后端扩展名清单逐项一致（含 `h`）；旧 `</script>` 误删在 typecheck 中即被拦截并修复。
